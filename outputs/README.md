# Outputs directory

The pipeline writes machine-readable evaluation and forecasting artifacts here. They
are generated from the current run and should be reviewed before being used as
portfolio evidence.

## Files

### `metrics.json`

Contains a JSON object with:

- `selected_model` — candidate with the lowest chronological-test RMSE;
- `train_rows` and `test_rows` — row counts after feature preparation;
- `seed`, `days`, and `forecast_horizon` — run parameters;
- `backtest_note` — distinction between observed-lag backtesting and recursive future
  forecasting;
- `models` — three records with `model`, `rmse`, `mae`, and `r2`.

### `metrics.csv`

Contains one row per candidate:

```text
model,rmse,mae,r2
SeasonalNaive,...,...,...
LinearRegression,...,...,...
RandomForestRegressor,...,...,...
```

The values are intentionally not hard-coded in this README. Read the file generated by
your exact command and environment.

### `forecast.csv`

Contains one row per future forecast period. The documented horizon is 24 rows. It
includes future timestamps, simulated exogenous drivers, holiday status, and predicted
`consumption_kwh`. These are point predictions; the pipeline does not create prediction
intervals.

## Run commands

```bash
python main.py --days 365 --forecast-horizon 24 --seed 42
python main.py --days 30 --forecast-horizon 24 --seed 42
python -m pytest -q
```

The pipeline overwrites artifacts at configured paths on a later run. Copy a report to
a versioned experiment directory if you need to preserve multiple runs.

## Interpretation

The final 20% of engineered history is the chronological backtest. RMSE is the model
selection criterion; MAE and R² provide additional context. Do not describe the
numbers as real facility accuracy. The future CSV is recursive and uses simulated
future drivers, so it should be described as a virtual scenario.
